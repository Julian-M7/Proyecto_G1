# RF-001 — Registrar la venta como orden independiente

> Ficha de requisito (ISO/IEC/IEEE 29148). Versión de la ficha: Propuesto (supuestos adoptados) · v1.0 (21/11/2026) · Julián Murcia. Plantilla Word equivalente: `fichas-requisito-29148.docx`.

| Campo | Contenido |
|---|---|
| **Identificador · tipo** | RF-001 · Funcional |
| **Enunciado** | **CUANDO el empleado confirme una venta con al menos un producto del catálogo y un método de pago, el sistema deberá registrarla como una orden independiente con número de recibo único, los productos, el valor total, el método de pago, la fecha y hora y el usuario que la registró.** |
| **Plantilla EARS** | Basada en evento (CUANDO). |
| **Justificación** | Hoy cada venta se anota dos veces (cuaderno y celular) y la lista del día no se divide por pedido; sin una orden independiente no se puede saber qué productos tuvo un pedido ni rastrear un descuadre como el de $50.000, cuyo origen nadie pudo establecer. |
| **Fuente** | Entrevista a la empleada (17/09/2026), hallazgos 2, 3 y 5; entrevista al jefe (fecha no registrada en el documento), hallazgos 1 y 3; acta de constitución, sección 7 (criterios 2 y 3). |
| **Propietario** | Camilo Gutiérrez — jefe y propietario (la empleada valida el flujo de venta). |
| **Trazabilidad hacia atrás** | NI-01, NI-02, NI-16 · G1.1, G1.2 · HU-01 |
| **Prioridad** | Must (supuesto de trabajo; backlog.md). |
| **Dependencias y conflictos** | RF-019 (rechazo de la venta incompleta), RNF-002 y RNF-006 (sin conexión y persistencia), RF-003 (descuenta stock), RF-006 (cierre). Corrige HU-01, escenario 2, que cancelaba la venta si fallaba la conexión. |
| **Método de verificación** | Prueba · CP-001 |
| **Criterio de aceptación** | En CP-001, con un catálogo de ejemplo y una jornada de 40 ventas (el máximo que menciona el jefe): (a) cada venta confirmada con producto y método de pago genera una orden con un número de recibo distinto, con el formato AAAAMMDD-NNN; (b) cada orden contiene los seis datos del enunciado; (c) cada orden se puede consultar por producto, por hora, por monto y por método de pago. |
| **Notas y supuestos** | Supuestos: «número de recibo» equivale al «número de comprobante» del jefe (P-05) y tiene el formato AAAAMMDD-NNN, consecutivo por día (TBD-17). * Depende de un supuesto de trabajo del apéndice C del SRS: el patrocinador valida «correcto» y quien construya valida «factible» en la fase 05. |
